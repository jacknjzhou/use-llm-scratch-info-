# 文件分类流程

## 概述

文件分类是智能信息提取系统的核心功能之一。当用户上传文件并创建自动匹配任务时，系统会自动识别文件类型并匹配对应的模板。

---

## 完整流程图

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                              文件分类完整流程                                 │
└─────────────────────────────────────────────────────────────────────────────┘

【1. 任务创建】
    用户上传文件 → 创建任务（match_mode="auto"）→ 任务状态: pending
                                          ↓
【2. Worker 接收任务】
    Celery Worker 抢锁 → 任务状态: running
                                          ↓
【3. 查询模板】
    SELECT * FROM extract_schema WHERE is_deleted = false
    → 获取所有可用模板（当前 10 个）
                                          ↓
【4. 文件分类循环】
    ┌─────────────────────────────────────────────────────────────┐
    │  for each task_file (match_status = "pending"):            │
    │                                                             │
    │  ┌─────────────────────────────────────────────────────┐    │
    │  │  classify_file(file_row, schemas, llm_cfg, db)      │    │
    │  └─────────────────────────────────────────────────────┘    │
    │                          ↓                                  │
    │  ┌─────────────────────────────────────────────────────┐    │
    │  │           分类入口函数（最终版）                      │    │
    │  │  backend/app/services.py:783                        │    │
    │  └─────────────────────────────────────────────────────┘    │
    └─────────────────────────────────────────────────────────────┘
                                          ↓
【5. 分类子流程】 classify_file_with_cache / classify_with_fallback
    │
    ├─→ [缓存检查] MatchCache.get(filename)
    │       ↓ 命中 → 直接返回缓存结果
    │       ↓ 未命中 → 继续
    │
    ├─→ [重试循环] max_retries=2 次
    │       │
    │       ├─→ classify_file_two_stage()
    │       │       │
    │       │       ├─→ [多页采样]
    │       │       │   parse_file(max_pages=3)
    │       │       │   sample_text_from_chunks() → 约5000字符
    │       │       │
    │       │       ├─→ [阶段一：粗筛] (模板数 > 5 时)
    │       │       │   _coarse_classify()
    │       │       │   → 轻量 Prompt，返回置信度 > 0.3 的候选（最多5个）
    │       │       │
    │       │       └─→ [阶段二：精排]
    │       │           _fine_classify()
    │       │           → 增强 Prompt，输出最优模板 + 置信度
    │       │
    │       ├─→ [动态阈值判断]
    │       │   calculate_dynamic_threshold()
    │       │   → 根据候选差距动态调整阈值（0.68~0.88）
    │       │
    │       └─→ [异常捕获] 失败则重试或回退
    │
    └─→ [缓存写入]
        置信度 ≥ 0.7 → MatchCache.set() → TTL 24小时
                                          ↓
【6. 更新文件状态】
    tf.match_confidence = match["confidence"]
    tf.match_reason = match["reason"]
    tf.matched_schema_id = match["schema_id"]
    
    判断逻辑：
    ┌──────────────────────────────────────────────────────┐
    │ schema_id == None OR confidence < 0.5                │
    │   → match_status = "unmatched"  (未匹配)              │
    │                                                       │
    │ confidence < 动态阈值 (默认 0.8)                      │
    │   → match_status = "need_confirm"  (需确认)           │
    │                                                       │
    │ confidence >= 动态阈值                                │
    │   → match_status = "bound"  (已绑定)                  │
    └──────────────────────────────────────────────────────┘
                                          ↓
【7. 逐文件提取】
    for each task_file (status != "succeeded"):
        if match_status == "unmatched" OR matched_schema_id == None:
            → status = "failed" (跳过提取)
        else:
            → extract_file() → 提取字段
            → status = "succeeded"
                                          ↓
【8. 任务完成】
    汇总状态 → status = "succeeded" / "partially_succeeded" / "failed"
```

## 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `classify_max_pages` | 3 | 分类采样页数 |
| `classify_max_chars` | 5000 | 采样最大字符数 |
| `classify_sample_strategy` | head_middle_tail | 采样策略 |
| `match_auto_threshold` | 0.8 | 自动绑定阈值 |
| `match_confirm_threshold` | 0.5 | 需确认阈值 |
| `match_dynamic_threshold` | True | 启用动态阈值 |
| `match_max_retries` | 2 | 最大重试次数 |
| `match_cache_enabled` | True | 启用缓存 |

## 返回值结构

```python
{
    "schema_id": "uuid或None",      # 匹配的模板ID
    "confidence": 0.0~1.0,          # 置信度
    "reason": "判断理由",           # 详细理由
    "matching_features": [],        # 匹配到的特征
    "match_status": "bound/need_confirm/unmatched",  # 最终状态
    "threshold_strategy": "调整策略", # 阈值计算说明
    "_candidates": [],              # 内部使用：候选模板列表
    "from_cache": False             # 是否来自缓存
}
```

## 各阶段详细说明

### 阶段一：多页采样

从文档中智能采样文本，用于后续分类判断。

**配置**：`classify_max_pages=3`, `classify_max_chars=5000`

**策略**：`head_middle_tail`
- 头部：前2页
- 中部：中间位置1页
- 尾部：最后1页

### 阶段二：粗筛

当模板数量 > 5 时，先用轻量 Prompt 快速排除明显不匹配的模板。

**Prompt 要点**：
- 只返回置信度 > 0.3 的模板
- 最多返回 5 个候选
- 禁止编造

### 阶段三：精排

对粗筛后的候选模板进行精细化分析。

**Prompt 要点**：
- 传入候选模板的详细信息（名称、分类、描述、关键字段）
- 要求输出详细的判断理由（20字以上）
- 给出匹配到的特征列表

### 阶段四：动态阈值

根据候选模板的分布动态调整阈值。

| 场景 | 调整策略 |
|------|----------|
| 单一候选 | 降低阈值 10% |
| 候选差距大（> 0.3） | 提高阈值 10%（最高 0.95） |
| 候选差距小（< 0.1） | 降低阈值 15% |
| 候选差距适中 | 使用默认阈值 |

### 阶段五：缓存

- **缓存键**：标准化文件名（去除数字、版本号）
- **TTL**：24小时
- **缓存条件**：置信度 ≥ 0.7

---

## 状态说明

| 状态 | 含义 | 后续处理 |
|------|------|----------|
| `bound` | 已自动绑定模板 | 直接进行字段提取 |
| `need_confirm` | 需要人工确认 | 等待用户在界面确认 |
| `unmatched` | 未匹配到模板 | 标记为失败，用户需手动指定 |

---

## 异常处理

1. **分类调用失败**：最多重试 2 次
2. **所有重试失败**：返回 `need_confirm` 状态而非 `unmatched`
3. **入口异常捕获**：确保不会因为单个文件分类失败导致整个任务崩溃

## 分类判断逻辑

### 核心原理

分类本质是**让 LLM 根据文档内容判断匹配哪个模板**，通过精心设计的 Prompt 来引导 LLM 进行语义理解和匹配。

### 判断依据

| 判断依据 | 说明 | 示例 |
|----------|------|------|
| **关键词匹配** | 文档中是否包含模板特征词 | "发票"、"合同"、"行程单" |
| **字段匹配** | 文档内容是否匹配模板定义的字段 | 发票号、金额、日期、税率 |
| **结构特征** | 文档排版格式是否符合特定模板的典型结构 | 合同条款、表格格式、标题层级 |
| **语义理解** | LLM 理解文档语义后判断类型 | 理解上下文，识别文档类型 |

### Prompt 设计

#### 粗筛 Prompt（`_coarse_classify`）

```
你是文档分类助手。根据文件名和文档片段，快速判断该文档可能属于哪个模板类别。

输入：
- 文件名
- 文档片段（前3000字符）
- 候选模板列表（只含名称和类别）

输出要求：
[
  {"name": "模板名", "confidence": 0.0~1.0},
  ...
]
- 返回置信度 > 0.3 的模板，最多 5 个
- 如果所有模板都不匹配，返回空数组 []
```

#### 精排 Prompt（`_fine_classify`）

```
你是专业的文档分类专家。根据给定的文档片段，从候选模板中选择最匹配的一个。

分类原则：
1. 优先依据文档中的关键字段/特征词判断（如合同编号、发票号码、金额格式）
2. 参考模板的字段定义，匹配度最高的优先
3. 注意文档的结构特征（合同条款、表格格式、标题层级等）
4. 如果候选模板都很接近，选择置信度最高的那个

输入：
- 候选模板详情（含：名称、类别、描述、关键字段）
- 文件名
- 文档片段（采样后约5000字符）

输出要求：
{
  "schema_id": "模板UUID",
  "confidence": 0.0~1.0,
  "reason": "详细判断理由（20字以上）",
  "matching_features": ["匹配特征1", "匹配特征2"]
}
```

### 判断流程示例

当上传一份**发票**文件时：

```
输入给 LLM：
├── 模板列表：
│   ├── 合同模板
│   ├── 行程单模板
│   ├── 增值税专用发票
│   ├── 普通发票
│   └── ...（共10个模板）
│
├── 文档片段：
│   "增值税专用发票
│    发票代码：1234567890
│    购买方名称：XXX公司
│    销售方名称：YYY公司
│    价税合计：￥1000.00
│    税额：130.00
│    税率：13%..."

└── 文件名：invoice.pdf

LLM 判断：
├── 匹配到"增值税专用发票"模板
├── 理由：文档包含"增值税专用发票"标识，有发票代码、税额、税率等特征字段
├── 置信度：0.95
└── 匹配特征：["增值税专用发票", "发票代码", "税额", "价税合计", "税率"]
```

### 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `classify_coarse_threshold` | 0.3 | 粗筛时置信度 > 0.3 才保留 |
| `match_auto_threshold` | 0.8 | 精排置信度 ≥ 0.8 自动绑定 |
| `match_confirm_threshold` | 0.5 | 置信度 < 0.5 标记为未匹配 |
| `classify_max_pages` | 3 | 分类采样页数 |
| `classify_max_chars` | 5000 | 采样最大字符数 |

### 简化流程（模板 ≤ 5 时）

当模板数量较少（≤ 5）时，跳过粗筛阶段，直接进行精排。此时 Prompt 会传入所有模板的详细信息。

### 置信度判定规则

```
┌─────────────────────────────────────────────────────────────┐
│  schema_id == None OR confidence < 0.5                      │
│    → match_status = "unmatched"  (未匹配)                    │
│                                                             │
│  0.5 <= confidence < 动态阈值 (默认 0.8)                     │
│    → match_status = "need_confirm"  (需人工确认)             │
│                                                             │
│  confidence >= 动态阈值 (默认 0.8)                           │
│    → match_status = "bound"  (已自动绑定)                    │
└─────────────────────────────────────────────────────────────┘
```

### Few-shot 示例

系统还会加载历史成功分类案例作为 Few-shot 示例，帮助 LLM 更准确地判断：

```
参考以下历史分类案例：
- 文件「合同2024.pdf」→ 模板「合同模板」(置信度: 0.92)
- 文件「发票_2024_001.pdf」→ 模板「增值税专用发票」(置信度: 0.95)
```
